# ADR-001: Reuse the HW5 subscription tracker for the individual final project

**Status:** Accepted as a prototype; deployed and tested with fictional data (2026-11-12), not secure for private user data  
**Date:** 2026-11-11

## Context
The individual final repo originally contained a generic starter page and optional Gemini Worker. HW5 contained a more complete, previously tested subscription dashboard with renewal dates and a Cloudflare D1 backend. Reusing it reduces implementation work and gives the final project a specific feature that can be tested against existing EARS requirements.

## The Gate
- **Build from scratch:** more learning, but repeats the existing page, backend, validation, and test work.
- **Buy an existing subscription tracker:** does not provide inspectable source code and could require paid services or personal data.
- **Reuse a previously built app:** preserves reviewed project-specific features and tests while requiring a fresh deployment and sourcing audit.

## Options considered
| Option | For | Against |
|---|---|---|
| Rebuild template | Simple start | No functional product |
| Buy/host a third-party tracker | Quick for users | Opaque, weak course traceability |
| Port HW5 app | Existing source, documentation, evals | Deployment/CORS work remains; shared-data risk |

## Decision
Port HW5's subscription dashboard (vanilla HTML/CSS/JavaScript), Cloudflare Worker, D1 schema, migration, lockfile, and API tests into this repository. Remove the unused starter Gemini Worker. Wrangler was initially pinned to `4.146.0` and later security-upgraded to exact-pinned `4.161.0` after four high-severity dependency findings; `npm audit` then returned zero vulnerabilities. Treat the transferred application as **a prototype**, not a private-account-ready financial product.

## Consequences
- **Benefits:** reuse of a functional, documented prototype and historical test records.
- **Costs:** deployment configuration and test reruns were needed and completed on 2026-11-12, plus external vendor dependencies and ongoing support of Cloudflare D1.
- **Privacy/security:** the API currently has no authentication, and any requester can read, create, or delete entries. CORS only limits which browser origins can read responses; it is not authentication. Use fictional data only.
- **Reversal trigger:** real user-specific records, pricing/limits changing, or the existing backend becoming unsuitable. Add authentication and user isolation before any real-user data collection.
- **Audit:** [docs/SOURCING-AUDIT.md](SOURCING-AUDIT.md) documents the risk scoring, rings, and exit options.

**Historical architecture:** [HW5's architecture record](https://github.com/GiancarloMartinez-Saldana/mgt3745-hw5/blob/main/context/ARCHITECTURE.md), also preserved in this repository's `context/ARCHITECTURE.md`.

## Follow-up verification (2026-11-12)

The user verified that local API tests passed 7/7, the version-pinned dependency upgrade cleared npm audit, the local D1 export step worked, Cloudflare deployed the Worker plus three static dashboard assets, and live save/reload/delete operations worked with fictional demo data. See [ADR-002](ADR-002.md) for the same-origin deployment decision. This does not resolve lack of user authentication or turn the prototype into a private-data-ready financial service.

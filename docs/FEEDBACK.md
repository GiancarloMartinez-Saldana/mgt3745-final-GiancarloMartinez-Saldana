# Real-User Task Feedback — collection plan, not results

**Prepared:** 2026-11-14. **0 new final-project usability interviews/task sessions have been recorded here.** The two September 10 exploratory interviews in [USERS.md](../context/USERS.md) are historical problem interviews; they must not be counted as app usability trials.

## Ethical and security boundary

The public Cloudflare demonstration has **no authentication** and all D1 rows are shared. No participant should enter actual streaming accounts, payment credentials, bills, names, email addresses or any private information. When using the public demo for a task, create only synthetic subscriptions and delete them afterward. The project owner should obtain consent before collecting any observation/quote; participant codes and roles only, never identities or identifying details.

## Future study — prospective; not performed

Recruit **at least 3 consenting adult** participants, if feasible, and ask each to complete these five tasks using **fictional** entries: add two services; read the calculated monthly total; add a third with a renewal date; reload and inspect persisted dates; delete a service and observe the total update. Observe whether steps require help, whether the participant recognizes that data are shared, and whether the participant would actually use the app for cost awareness. Do not imply that a successful task proves actual financial benefit.

**Decision threshold:** For initial public demo usability, seek **3/3 unaided** completions of basic save/read/reload/delete. **Any** request to enter private real-world financial data triggers a stop until user authentication and separation are verified. These are prospective thresholds adopted in [DECISION-001](DECISION-001.md), not claims of data collected already.
